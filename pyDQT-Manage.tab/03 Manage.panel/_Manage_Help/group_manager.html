Group Manager

by Dang Quoc Truong (DQT)

Groups

Manage Toolset›Group Manager

What it does

Lists every Model and Detail group type in the model with its instance count, the view(s) and sheet(s) it is used in, its creator and workset, and lets you drill into a type to see exactly which view and sheet each of its instances lives in.

Stat cards

Total Types
group types found (Model + Detail)
Model
Model group types
Detail
Detail group types
Selected
rows currently ticked in the grid

View and Sheet columns

View
the view(s) the type's instances are in
Sheet
the sheet(s) those views are placed on, as number - name; Not on a sheet when none of them is

Detail Group types fill in as soon as the tool opens - a detail group belongs to one view. A Model Group shows in every view that can see it, so the only way to know is to ask each view; its cells read (scan needed) until you select the Model type(s) you want and click Scan Selected. Only the selected types are scanned - nothing else in the model is touched. The scan shows a progress bar you can cancel (a cancelled scan keeps nothing), and its result is kept per type until Refresh (placements may have changed); scanning more types later adds to it. Clicking Detail on a Model type scans just that one type, so the grid fills in for it then too.

A long list shows its first 3 entries and (+N more); Detail and Export CSV have all of them.

Filters

Search
matches name, creator, workset, view or sheet - type a sheet number to find every group used on it
Category
All / Model only / Detail only

Workflow

  1. Search / filter by Category to find the group type(s) you care about.
  2. Select in Model or Zoom To the ticked type's instances.
  3. Select the Model Group type(s) you care about and click Scan Selected to fill in their View / Sheet.
  4. Detail opens a breakdown of the selected type - which view(s) and sheet(s) each of its instances is in, with its own Select in Model / Zoom To.
  5. Export CSV saves the current (filtered) list; Refresh reloads it; Close exits the tool.

Good to know

A type with an Instances count of 0 is loaded but unplaced - a purge candidate if it's not needed. Its View and Sheet read -.
The scan is light on a big model. It used to walk every group in every view and build an element object for each one - enough to run Revit out of memory on a large model. It now scans only the types you select, asks each view just about those instances (Revit answers with ids, so no group element is created), and skips views that can never show a model group (sheets, schedules, legends, drafting views and reports).
