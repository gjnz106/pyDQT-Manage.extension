Manage Toolset›Family Manager

What it does

A tabbed manager covering loadable families, system families (Walls, Floors, Ceilings, Roofs) and Model Groups in one place: rename, delete, purge unused, edit and compare parameters, check family names against your own naming rules, and round-trip families out to disk for editing and back in.

Tabs

Families
every family (loadable, system, and groups), searchable and filterable by kind and by All/With Issues/Unused; Select Unused / Purge Unused clear out loadable families with zero instances
Type Manager
pick a family, then Rename / Duplicate / Delete / Activate one of its types, or Select Instances of it in the model
Parameters
pick a family and type, filter by All/Type Only/Instance Only/Shared, Edit a value, Copy it to other types, CSV round-trip, or Compare values across every type in the family
Naming Check
define per-category naming rules (name must Prefix/Suffix/Contain/match a Regex pattern), run them, and export the rule set or the results report

Workflow

  1. Pick a tab, then filter by Loadable/System/Groups (Families tab) as needed.
  2. Rename and Delete act on the current tab's selection - available from the Families tab or Type Manager only.
  3. All / Clear select or deselect every row in the current grid.
  4. Export saves the selected Loadable families as .rfa files to a folder you pick (system families and groups can't be exported) - edit them in Revit, then Import loads the edited files straight back in, always overwriting the project's existing copy.
  5. CSV / Report export the Families grid to a CSV or an HTML report; Refresh reloads everything from the model.
  6. On the Naming Check tab: add one or more rules, Run Naming Check, then Export Report for the violations, or Import/Export Rules to reuse a rule set on another project.

Good to know

Rename and Delete are only wired up for the Families tab and Type Manager - Parameters and Naming Check are for editing values and checking names, not renaming/deleting the family itself.
Export no longer purges anything on its own. It only asks whether to overwrite an existing file at the destination. To purge unused families first, use Purge Unused on the Families tab (or the dedicated Purge Families tool) before exporting - keeping "export" and "delete" as two separate, deliberate steps.
Export → Purge Families → Import now reloads every changed family, not just the ones that happened to have no name conflict. Every family Import picks up already exists in the project by definition - that is the whole point of the round trip - and Revit's own "Family Already Exists" prompt used to be asked with nobody there to answer it, so only a handful ever actually came back in. Import now answers that prompt itself (always overwrite, with the reloaded copy's parameter values) instead of leaving it unanswered.
