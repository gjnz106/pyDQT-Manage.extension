Batch Purge Families v1.0

by Dang Quoc Truong (DQT)

On disk

Cleanup Toolset›Purge Families

What it does

Opens every .rfa file in a folder, purges unused elements until Revit reports the file is clean, saves it back, and reports what (if anything) is left. Works on a folder of family files on disk - not on the families loaded into the current project.

Workflow

  1. Browse - select the folder containing the .rfa families.
  2. Scan Folder - finds every .rfa file and previews it with its size.
  3. Start Purge - each file is opened, purged, saved, and reopened, repeating until nothing purgeable is left.

Why the reopen cycles

Revit only finalises part of its reference bookkeeping when a file is written. Elements still held after an in-memory purge only become purgeable once the file has been saved and read back - purging in a single open session leaves that tier behind, which is why the native Purge Unused dialog can still list items afterwards. Reopen cycles repeat save → reopen → purge until a freshly opened file reports zero.

The Remaining column

Every file is verified after its last purge pass. Status reads Success only when Revit reports 0 purgeable elements left. Partial means something is protected and cannot be removed - the count tells you how much.

Rename files

A loadable family is named by its file, so renaming the .rfa renames the family - nothing has to be opened, which is why this runs instantly even on hundreds of files. Find/Replace, Prefix, Suffix, Case and Remove spaces all combine in one pass. The list previews every old → new name before you commit, and Rename Files asks again first.

Skipped files say why: two files resolving to the same name, a name already taken, or characters Windows won't accept. Renaming is independent of purging - run either, or both. Families already loaded into a project keep their old name until they're reloaded.

Good to know

Files are overwritten in place - back up the folder first if you need to keep the originals.
