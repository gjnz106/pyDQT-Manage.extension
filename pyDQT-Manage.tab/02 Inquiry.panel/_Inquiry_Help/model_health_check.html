Model Health Check

by Dang Quoc Truong (DQT)

Score dashboard

Inquiry Toolset›Model Health Check

What it does

Analyzes the model against 12 metrics, grades each one Green, Amber or Red, and combines them into one weighted health score. The metrics are listed by their impact on model performance and stability, so the dashboard shows first what hurts the model most.

Health scale (RAG)

Every metric, and the model as a whole, is graded on three levels:

Green
healthy, meeting expectations
Amber
needs attention, improvement recommended
Red
action required, high risk or major impact

A metric is Green up to its Green value, Amber up to its Amber value, and Red above that. The overall result comes from the weighted score (Green 100, Amber 50, Red 0 per metric): Green from 90, Amber from 60, Red below 60.

Metrics by impact

Critical impact
1. Warnings · 2. CAD Imports · 3. File Size · 4. In-Place Families - the most likely to cause performance issues, instability, file bloat and user frustration
High impact
5. Duplicate Elements · 6. CAD Links · 7. RVT Links - affect manageability, model quality and long-term maintainability
Moderate impact
8. Imported Images · 9. Model Groups · 10. Design Options
Low impact
11. Unplaced Rooms · 12. Unpinned Links - model housekeeping rather than performance issues

Each metric's default weight in the overall score follows its impact: Critical 5, High 4, Moderate 3, Low 2.

Workflow

  1. (Optional) Open the Settings tab first to adjust any metric's Green / Amber values or weight to match your own standards, before running an analysis.
  2. Re-Analyze re-runs all 12 metrics against the current model.
  3. Read the overall result under the gauge, then go down the dashboard: it is grouped Critical, High, Moderate, Low impact, so the Red and Amber rows at the top matter most.
  4. The recommendations list every Amber and Red metric, in the same priority order. Select on a row selects the offending elements straight in Revit.
  5. Export Report saves the dashboard as an HTML report (print it to PDF from the browser).

Good to know

This tool only reads the model - fixing a flagged metric (purging unused content, resolving warnings, converting in-place families, etc.) means switching to the matching tool elsewhere in pyDQT.
New in v2.0. The 6-level scale (Good / Acceptable / Warning / Concerning / Critical / Severe) is now Green / Amber / Red: Green is the old Good and Acceptable, Amber the old Warning, Red the old Concerning and worse. The metrics are listed by impact instead of by how bad they are. Model Groups now counts model groups only - detail groups are view annotation, not part of the model's performance. The report header now always shows the overall result (it could show the name of the last recommended metric instead).
Settings tab. Every metric's Green value, Amber value and weight (1-5, how much it counts toward the overall score) can be edited directly, right next to the Dashboard tab. Save & Apply writes the change to threshold_config.json next to this tool - so it survives closing Revit - and immediately re-scores the dashboard from the last analysis. Reset to Defaults restores the built-in values and deletes that file. A row with an invalid value (not a number, or Green above Amber) blocks the whole save rather than silently accepting the other 11. A settings file saved by v1.x is converted on the fly: its old thresholds become Green / Amber the same way as above, and weights left at their old default take the new impact-based default.
CAD Imports counted 0 in models that still had imported CAD. Two causes, both fixed. The Import/Link test read ImportInstance.IsLinked directly, which is missing on some Revit 2026 builds - and the bare except around it silently dropped the element from both CAD Imports and CAD Links rather than flagging it. It now goes through the same shared check CAD Import Manager uses, so the two tools cannot disagree. The metric also now counts CAD types left with no instances: Revit never auto-deletes a type when its last instance goes, and ACC's Model Analytics reports CAD at the type level, so those orphans stayed invisible here while ACC kept reporting them. Clear them with Purge Unused Types in CAD Import Manager.
