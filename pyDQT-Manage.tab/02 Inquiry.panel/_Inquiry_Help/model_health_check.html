Model Health Check

by Dang Quoc Truong (DQT)

Score dashboard

Inquiry Toolset›Model Health Check

What it does

Analyzes the model - and the Revit links you tick - against 15 metrics, grades each one Green, Amber or Red, and combines them into one weighted health score per model. Everything is shown at once: an Overview of every model, and one dashboard tab per model. The metrics are listed by their impact on model performance and stability, so each dashboard shows first what hurts the model most.

Health scale (RAG)

Every metric, and the model as a whole, is graded on three levels:

Green
healthy, meeting expectations
Amber
needs attention, improvement recommended
Red
action required, high risk or major impact

A metric is Green up to its Green value, Amber up to its Amber value, and Red above that. The overall result comes from the weighted score (Green 100, Amber 50, Red 0 per metric): Green from 90, Amber from 60, Red below 60.

Metrics by impact

Critical impact
1. Warnings · 2. CAD Imports · 3. File Size · 4. In-Place Families - the most likely to cause performance issues, instability, file bloat and user frustration
High impact
5. Duplicate Elements · 6. CAD Links · 7. Unused Families & Types - affect manageability, model quality and long-term maintainability
Moderate impact
8. Imported Images · 9. Design Options · 10. Materials
Low impact
11. Line Styles · 12. Line Patterns · 13. Fill Patterns · 14. Unplaced Rooms · 15. Unpinned Links - model housekeeping rather than performance issues

Each metric's default weight in the overall score follows its impact: Critical 5, High 4, Moderate 3, Low 2.

Unused Families & Types
the families and types Revit's own Purge Unused would remove (Green up to 100, Amber up to 300). Read with GetUnusedElements on Revit 2025+, GetAllUnusedElements on 2024, and Revit's Performance Adviser rule "Project contains unused families and types" on older versions; the note under it splits families and types.
Materials
every material in the model (Green up to 200, Amber up to 400); the note says how many are not used anywhere.
Line Styles
the subcategories of Lines - what the Line Styles dialog lists (Green up to 100, Amber up to 200).
Line Patterns
every line pattern (Green up to 50, Amber up to 100); the note says how many came in with CAD imports (named IMPORT-...) and how many are unused.
Fill Patterns
every drafting and model fill pattern (Green up to 150, Amber up to 300); the note splits drafting / model and counts the unused ones.

The "unused" counts in the notes come from the same Purge Unused list (Revit 2024+); on older versions only the families and types are available. All the values can be changed on the Settings tab.

Workflow

  1. Start the tool. When the model has Revit links, a list comes up first: the open model is always checked; tick the links to check with it (Select All / Clear All help with long lists), then click Run Check. Cancel stops here. A model without links goes straight to its dashboard.
  2. Every checked model is analysed straight away and the window shows them all at once: the Overview tab, one dashboard tab per model - its dot is the model's overall colour - and Settings.
  3. On a model's tab, read the overall result under the gauge, then go down the dashboard: it is grouped Critical, High, Moderate, Low impact, so the Red and Amber rows at the top matter most.
  4. The recommendations list every Amber and Red metric, in the same priority order. On the open model's tab, Select on a row selects the offending elements straight in Revit.
  5. Re-Analyze on a tab re-reads that model; Re-Analyze All on the Overview re-reads every checked model.
  6. Export Report - on the Overview or any model's tab - first asks where to save the report and in which format: PDF (the default) or HTML. The report holds everything: the Overview, then every checked model's score card, metrics and recommendations, each model on a page of its own. It opens as soon as it is saved, and the next export starts in the same folder.

Overview tab

One table with every model of the check: the open model first, then every Revit link in the model - one row per linked file, however many times it is placed - all graded with the same 15 metrics and thresholds.

Type / Instances
open model or linked model, and how many times a link is placed
Checked
analysed in this check - it has its own tab
Not checked
loaded, but not ticked at start - run the tool again and tick it
Not loaded
cannot be read - reload it in Manage Links first

For a checked model: Overall (Green / Amber / Red), Score, how many metrics are Red and Amber, and Needs Attention - the Red metrics first, then the Amber ones. View on a row opens that model's tab. When only the open model is checked, the window opens on its dashboard instead of the Overview.

Good to know

This tool only reads the model - fixing a flagged metric (purging unused content, resolving warnings, converting in-place families, etc.) means switching to the matching tool elsewhere in pyDQT.
Linked models. Each ticked link is read like a model of its own, so ticking many large links makes the check take longer - tick only the ones you need. A link that is not loaded cannot be ticked: reload it in Manage Links first. A linked model's dashboard is read-only: elements inside a link cannot be selected from the host model. The Settings tab grades every checked model - they are all re-graded straight away when a threshold changes. Links nested inside another link are included only when Revit shows them in this model.
PDF export. The PDF is printed by Microsoft Edge - already on every Windows 10 / 11 computer - running hidden in the background (Google Chrome is used when Edge is missing), A4 landscape, without the browser's date / file-path header and footer. It takes a few seconds; the cursor shows it is working. If neither browser can be used, the full report is saved as .html next to the chosen file instead and opened in your browser - print it from there with Ctrl+P › Save as PDF. If the export says the file cannot be written, close it in your PDF viewer and export again.
File Size of a cloud model (ACC / BIM 360 / Forma) is not graded. ACC's Size column shows the size of the last published version - a clean copy written when the model is published, so it does not change with syncs until someone publishes again. The only file of a cloud model on this computer is the copy Revit keeps in its collaboration cache (the folder set under Options › Cloud Model, else %LOCALAPPDATA%\Autodesk\Revit\Autodesk Revit <version>\CollaborationCache), and that copy is never compacted: it grows with every sync and can be many times larger - 740 MB in the cache for a model ACC lists at 95 MB. So File Size shows N/A and is left out of the score; the note under it gives the cache copy's size for reference (hover it to see the file). For the real size, use ACC's Size column after a fresh publish.
N/A. A metric shows N/A, and is left out of the score, when it cannot be measured or graded fairly: File Size of a model that has never been saved or of a cloud model, and Unused Families & Types on a Revit version without a purge list. The note under the metric says why.
New in v2.6 - ACC File Size no longer graded on the cache. v2.4 graded a cloud model's File Size on Revit's cache copy, which is never compacted - a model ACC lists at 95 MB was graded Red at 740 MB. It now shows N/A, out of the score, with the cache size in the note only.
New in v2.5 - metrics changed. Model Groups and RVT Links are no longer graded (linked models are still listed on the Overview, and unpinned RVT links still count under Unpinned Links). Five metrics are added: Unused Families & Types (High), Materials (Moderate), Line Styles, Line Patterns and Fill Patterns (Low). A settings file saved before keeps its values for the other metrics; the new ones start at their defaults.
v2.4 - File Size of ACC models. Read the copy in Revit's collaboration cache by the model's GUID. Since v2.6 that size is shown for reference only (see above).
New in v2.3 - choose where to save, PDF straight away. Export Report used to drop an HTML file on the Desktop and leave the PDF to Ctrl+P. It now asks where to save first and writes the PDF itself. The PDF shows the whole report: table headers repeat when a table runs onto the next page, a row is never cut in half, and long file names (e.g. TBS_WHE_ARC_B_ZZ_ZZ_M3_W_0001) wrap inside their column instead of pushing the page wider or shrinking it.
New in v2.2 - everything at once. The Linked Models tab, where each link had to be analysed and then opened in a window of its own, is replaced: tick the links to check before the check runs, and every checked model is shown at once - the Overview, one dashboard tab per model and Settings. Export Report now puts every checked model in one report.
New in v2.0. The 6-level scale (Good / Acceptable / Warning / Concerning / Critical / Severe) is now Green / Amber / Red: Green is the old Good and Acceptable, Amber the old Warning, Red the old Concerning and worse. The metrics are listed by impact instead of by how bad they are. Model Groups now counts model groups only - detail groups are view annotation, not part of the model's performance. The report header now always shows the overall result (it could show the name of the last recommended metric instead).
Settings tab. Every metric's Green value, Amber value and weight (1-5, how much it counts toward the overall score) can be edited directly on its own tab. Save & Apply writes the change to threshold_config.json next to this tool - so it survives closing Revit - and immediately re-scores every checked model from the last analysis. Reset to Defaults restores the built-in values and deletes that file. A row with an invalid value (not a number, or Green above Amber) blocks the whole save rather than silently accepting the others. A settings file saved by v1.x is converted on the fly: its old thresholds become Green / Amber the same way as above, and weights left at their old default take the new impact-based default.
CAD Imports counted 0 in models that still had imported CAD. Two causes, both fixed. The Import/Link test read ImportInstance.IsLinked directly, which is missing on some Revit 2026 builds - and the bare except around it silently dropped the element from both CAD Imports and CAD Links rather than flagging it. It now goes through the same shared check CAD Import Manager uses, so the two tools cannot disagree. The metric also now counts CAD types left with no instances: Revit never auto-deletes a type when its last instance goes, and ACC's Model Analytics reports CAD at the type level, so those orphans stayed invisible here while ACC kept reporting them. Clear them with Purge Unused Types in CAD Import Manager.
A DWG linked from the cloud counted as a CAD Import. A link whose Manage Links Path Type is Cloud (Autodesk Docs / Forma) is an external resource, not an external file reference, and the shared Import/Link check took "not a file reference" to mean "import". It now uses Revit's own IsLinked answer, and on builds without it counts a cloud reference as a link - so a cloud link is counted under CAD Links (and Unpinned Links when it is not pinned). A CAD type left behind by a link is no longer counted as a CAD Import either.
