What it does

Checks that the parameters CORENET X requires actually exist and carry a value on the model's elements, then lets you select, zoom to, or isolate the failing ones straight in Revit.

This is the QA pass - run it last, after the other four tools, and again just before a submission to confirm nothing regressed.

Stat cards

PARAMS / CATEGORIES
Size of the selected requirement set
PASSED
Every element has the parameter filled in
FAILED
No element has it - usually the parameter is absent
PARTIAL
Some elements have it, some do not
NO ELEM
Nothing of that category exists in this model

Workflow

  1. Load a config - Import XML (Autodesk Model Checker export), Import Excel, or pick a previously saved one.
  2. Select the disciplines and categories to cover - click anywhere on a row to select it, Shift+Click for a range, or use Tick All / None / Invert. Selected rows are filled blue across the whole row.
  3. Run Check, then filter the results (All / Failed / Partial / Passed) or search by name.
  4. Fold the results down to what you're working on - click a discipline band (ARC, STR…) or a category band (Doors, Curtain Systems…) to collapse or expand it. The chevron on the band shows which way it is: ▾ open, ▸ folded. Collapse All folds every category down to its one-line header and progress bar; Expand All opens everything back up.
  5. Detail on a failed or partial row opens the list of the elements that are actually missing that parameter - Element ID, Category, Type and Name. Search the list, click a row to select and zoom to that one element, or use Select All / Zoom All for the whole list.
  6. Tick result rows (Select All / Un-select / Invert / Tick Failed, or Shift+Click for a range), then:
    • Select Ticked in Revit - sets the Revit selection
    • Zoom To Ticked - selects and frames them in the active view
    • Isolate Ticked - temporarily isolates them; Reset Isolate/Hide brings everything back
    Zoom, Isolate and Reset all minimise this window right after they run, since the tool sits centred over the middle of the screen - exactly where a freshly-framed view lands - so without that you would not actually see the change. Restore it from the taskbar to keep going.
  7. Export Excel writes Summary / Detailed / Failed sheets - the record to attach to a submission. This writes the .xlsx directly and does not need Microsoft Excel installed on the machine.

Good to know

A category the tool cannot collect elements for is marked not supported rather than being reported as simply empty, so you are not misled into thinking it passed.
Type parameters are checked too, not just instance parameters - a value inherited from the Family Type counts as present.
Toposolid (Revit 2024+) and Topography (older Revit) are both recognised automatically.
What you fold stays folded - switching the All / Failed / Partial / Passed filter or re-running the check redraws the list but keeps the same sections collapsed. Select All only ticks rows you can actually see, so a folded-away category is never swept into the selection by accident.
The per-parameter Detail list, like the Select buttons, works from the element ids the check stored - the first 1000 per parameter. If a parameter is missing on more than that, the list says so rather than pretending it is complete.
If Zoom/Isolate/Select ever fails - a view that cannot be isolated, a locked document - a popup names the error instead of only updating the small status line at the bottom, which was easy to miss.
Select, Zoom, Isolate and the Detail list all resolve the ids the check stored back into Revit elements with a fallback chain rather than one fixed conversion - so if a future Revit release changes what that conversion needs (as 2026 did elsewhere in this suite), a row still turns into a live element instead of showing "not found" for everything.
Export Excel no longer goes through Microsoft Excel at all - it writes the .xlsx file directly, so it works on machines where Excel is not installed or, as on some Microsoft 365 Click-to-Run installs, is installed but does not register the Office component the old export path needed. A model with any category that has no elements in it - common on most real projects - used to make the export fail outright; that is fixed too.
