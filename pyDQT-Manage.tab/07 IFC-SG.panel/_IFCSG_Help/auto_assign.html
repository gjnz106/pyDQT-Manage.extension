What it does

Assigns the IFC export class to every Family Type in the model in one pass, by matching each type's name against the IFC+SG Industry Mapping (an LTA-style Excel file, or the tool's built-in table).

This is the bulk pass - it covers most of the model at once. What it cannot match with confidence is left for Subtype Definer or Manual Assign to finish by hand.

Stat cards

CATEGORIES
Revit categories found in the mapping
ELEMENTS
Elements those categories hold in this model
UNMATCHED
Types no mapping entry could be found for
SOURCE
Where the mapping came from - Excel file or the built-in table

Workflow

  1. Pick the mapping source: an Industry Mapping Excel file, or the built-in table.
  2. Review the preview grid - filter by search, category or source (Matched / Unmatched / built-in).
  3. Select rows (Ctrl/Shift+Click for several) and use Change IFC to fix anything unmatched.
  4. Choose Overwrite (replace every value) or Empty only (only fill in blanks, leave existing values alone).
  5. Apply Assignment writes the result to every Family Type's Export to IFC As parameter.

Predefined vs USERDEFINED

The Industry Mapping marks a subtype with a leading * when it needs the generic IFC entity plus a custom object type, instead of a named predefined type:

Mapping entryExport to IFC AsIfcObjectType
IfcDoor.DOOR (no *) IfcDoor.DOOR(empty)
IfcDoor.*BLASTDOOR (with *) IfcDoorBLASTDOOR

This rule is applied automatically - you never need to work out which case you are in.

Good to know

A category the tool has no mapping entries for at all is not treated as an error - it just will not appear in the preview.
Run this after Parameter Loader so the Export to IFC As / IfcObjectType parameters already exist to write into.
