What it does

Assigns the IFC export class element by element, for the elements in the active view. Use it to fix the handful of elements Auto Assign or Subtype Definer could not map, or to override a value on a specific element rather than its whole type.

This is the finishing tool - run it last, after the bulk tools, on whatever the IFC-SG Checker flags as still missing.

Stat cards

ELEMENTS SHOWN
Elements passing the current filters
ASSIGNED
Of those, how many already carry an IFC class
NOT ASSIGNED
Of those, how many are still empty
TICKED FOR CHANGE
Rows the Apply / bulk buttons will act on

Workflow

  1. Narrow the list with Search (name or Element ID), Category and Current IFC.
  2. Tick the rows you want to change - Tick All / Untick All help when most of a filtered list needs the same treatment.
  3. Set the class per row in New IFC Export As, or pick one class in the bulk dropdown and press Apply to Ticked to set it on every ticked row at once.
  4. Apply Changes to Revit writes the Export to IFC As parameter, and IfcObjectType too for any subtype marked * in the mapping.

Dropdown values

(Keep Current)
Leave this element untouched - the default for every row.
(Clear)
Blank both parameters.
Everything else
Comes from the IFC-SG mapping for that element's category - a * prefix marks a USERDEFINED subtype, same convention as Auto Assign and Subtype Definer.

Good to know

Filtering never loses your ticks or your dropdown choices - they are kept per element until you close the window.
Reload from Revit re-reads the current values and resets every pending choice back to (Keep Current).
Export Report writes the currently visible rows to a CSV file - handy for a before/after record.
A Family/Type name containing a comma (e.g. "Door, Blast") now survives the CSV export correctly, quoted per the CSV standard - an earlier version replaced the comma with a semicolon instead, silently changing the name shown in the report to one that no longer matches anything in the model.
Picking a * subtype (e.g. IfcDoor.*BLASTDOOR, Blast Door) now writes correctly: the bare entity IfcDoor goes to Export to IFC As and BLASTDOOR goes to IfcObjectType - an earlier version wrote the whole marked string, asterisk included, straight into Export to IFC As, which is not a value any IFC export or checker recognises. Current IFC now shows IfcDoor (BLASTDOOR) for such elements so the custom subtype stays visible instead of only showing the bare entity name.
A Curtain Wall element's own Revit category is "Walls" - curtain walls are a Wall Type, not a separate category - so its per-row dropdown now also offers the mapping's IfcCurtainWall entry alongside the regular Wall ones. It was reachable only through the bulk-assign dropdown before, which lists every entity regardless of category.
